# v1.4.5 左键与拖动修复验证

日期：2026-10-18。验证对象为 v1.4.5 Windows x64 便携包。

## 故障线索与修复

用户报告非全屏也会左键无响应、无法拖动；回到初始位置不能恢复，重载配置和重启可以恢复。此现象指向持久窗口输入状态，尚不能证明每次历史故障均由同一原因触发。

- 普通桌宠窗口创建时保留可聚焦能力，仍用 `showInactive()` 显示；不再随 input-busy 的按下/松开切换 `setFocusable`，恢复显示时也不改变该属性。避免在输入事件链中修改原生激活状态。
- 主进程处理延迟的不可交互请求时也遵守拖动租约，光标移出窗口不能使正在捕获鼠标的窗口重新穿透。
- Windows 转发鼠标移动的按键标志可能为零，只有鼠标捕获也已丢失才执行丢失松手恢复，避免仍按住时提前结束拖动。
- 松手显式释放当前指针捕获并清空编号，忽略其它指针的结束事件。

核对所用 Electron 43.3.0 官方源码：

- [SetFocusable 实现](https://github.com/electron/electron/blob/v43.3.0/shell/browser/native_window_views.cc#L1327-L1339)：修改窗口激活样式，禁用时还会执行 Focus(false)。
- [鼠标转发实现](https://github.com/electron/electron/blob/v43.3.0/shell/browser/native_window_views_win.cc#L688-L711)：转发 WM_MOUSEMOVE 时 wParam 固定为零。

- 隐藏/显示、重复进入/退出控制模式后点击拖动、菜单、DDL、缓存、聊天缺失服务错误处理、退出清理均通过。测试使用隔离数据，不发送真实聊天。
- 未执行用户此前取消的全屏焦点检查。自动化鼠标事件不等同于长时间真人桌面操作；本次未声称完整复现用户所有历史偶发故障。
