# v1.3.2 兼容性与验证

验证日期：2026-10-17。目标发布平台为 Windows 10/11 x64；实际桌面验证环境为 Windows 11 x64（10.0.26200），Node.js 24.19.0、Electron 43.3.0，主屏缩放 125%。Windows 10、不同显卡、多屏组合及所有真实游戏没有逐一实机验证；不据此声称所有用户环境都已通过测试。

## 本次修正

- 路径：启动入口使用 `fileURLToPath`，避免把 Windows 盘符、中文、空格和 `#` 的 URL 编码当文件路径。
- 首次启动：便携包带 Node.js、Electron、动画和默认配置。配置与会话写入当前用户目录；程序文件检查失败会提示完整解压，升级不覆盖用户自定义语录。
- 端口：管理程序请求系统分配空闲端口，正确读取后台实际地址；修正命令行对端口 `0` 的校验。后台绑定 `127.0.0.1`，管理请求使用每次启动生成的令牌。
- Codex 查找：额度和聊天统一识别 `CODEX_PET_CODEX_PATH`，兼容 `DSH_PET_CODEX_PATH`；支持桌面版的版本子目录、PATH 原生程序及常见 npm 原生程序布局。无效的显式路径会报错，不悄悄切换到另一份安装。
- 模型：新用户默认从账号实际 `model/list` 中选择支持 low 的推荐模型；手动 Sol/Luna 模式保留，缺少对应模型时明确报错。
- 网络：后台沿用显式代理变量；未设置时尝试读取 Windows 已启用的 HTTP(S) 系统代理，只作用于子进程。回环连接排除代理。不实现 PAC、代理认证交互或所有 SOCKS 布局。
- 超时与错误：聊天不自动重发，桌宠输入框与后台的等待上限匹配；管理窗口展示具体操作错误。
- 桌面：尝试恢复 Codex 或按 `CODEX_PET_APP_PATH` 启动自定义桌面程序；全屏状态继续控制显隐，不持续强制压过前台应用。
- 构建：独立版构建直接使用当前 Node.js 启动工具，避免对子进程中全局 npm 路径的依赖；发布包仅安装锁文件中的生产依赖。

## 发布包桌面实测

在全新临时用户数据目录中，把便携包移到包含 **中文、空格和 `#`** 的路径后启动，验证：

- 首次启动创建默认配置，使用包内 Node.js 与 Electron，透明 WebM 动画成功解码。
- 无 Codex 的模拟环境中，动画、语录、显示/隐藏、管理窗口与会话操作可用；额度和聊天显示明确错误，失败后可继续操作。
- 新建、切换、刷新恢复聊天历史，模型模式及画像开关持久化。
- 单实例、关闭留托盘、正常退出释放后台端口。
- 本机匿名 HTTP 请求被拒绝，无法读取管理接口的聊天数据。
- 真实账号额度成功显示；关闭画像后，用一句固定测试消息验证自动模型真实回复。
- 重置按钮能完成查询或明确提示网络失败；打开 Codex 时播放敬礼动作。
- 用真实全屏测试窗口验证：桌宠隐藏、全屏窗口保持焦点，关闭全屏后桌宠恢复。

实测脚本为 `tests/portable-smoke.cjs`。默认模拟未安装 Codex，不发送聊天；需本机已登录账号时，可显式设置 `CODEX_PET_TEST_LIVE=1`，会发送一条固定测试消息并消耗少量账号额度。测试创建独立临时数据，不改动正常用户的聊天与偏好。

## 环境差异及处理

| 环境 | 行为或处理 |
| --- | --- |
| 未安装 Codex / 未登录 | 本地陪伴仍可用；安装并登录后重新刷新 |
| API Key 登录 | 无 ChatGPT 订阅额度；不伪造剩余额度 |
| 账号没有 Sol/Luna | 主动选择“自动”；已有选择不会被擅自更改 |
| Codex 放在自定义路径 | 设置 `CODEX_PET_CODEX_PATH` 指向真实 CLI；桌面程序另用 `CODEX_PET_APP_PATH` |
| 自定义 Codex 数据目录 | `CODEX_HOME`；为空时使用当前用户的 `.codex` |
| 旧版或未来版没有状态数据库 / 表结构变化 | 状态监测降级，本地动画和其他模块继续运行；需要按客户端结构适配 |
| 网络不可达或额度接口报错 | 显示失败原因，不把失败当成 0% 已用，不自动重发聊天 |
| 发布包缺文件 / 未完整解压 | 启动时说明缺失文件，重新完整解压 |
| Windows ARM64 / macOS / Linux | 本次没有发布或承诺可用的安装包 |
